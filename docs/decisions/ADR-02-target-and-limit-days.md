# ADR-02. Целевая величина, сессии и лимитные дни

**Статус:** Proposed
**Дата:** 2026-09-27
**Затрагивает:** §2.5, §3 (таблица, B3), §4, §9 (фаза 2) спецификации v0.2
**Тип:** [ADR]

## Контекст

- §2.5: дни лимита — цензурированные наблюдения, «модель обязана трактовать их как цензурирование».
- §3 (таблица): цензурированное правдоподобие — в B3.
- §9: цензурирование лимитных дней — в фазе 2 (B2).
- §4: целевая — распределение логарифмической доходности контракта на горизонте H.

Противоречие §3 ↔ §9 и отсутствие правил для B0/B1 и для scoring.

## Решение (предлагаемое)

### 1. Разделение объектов

| Объект | Обозначение | Определение |
|---|---|---|
| Опубликованная settlement-цена | `S_obs(c, τ)` | Официальный daily settlement контракта `c` за сессию `τ` (лицензированный EOD, с учётом опубликованных исправлений по PIT, ADR-03) |
| Скрытая цена | `S*(c, τ)` | Ненаблюдаемая «равновесная» цена, которую settlement отражал бы без лимита; существует только внутри модели B2+ |
| Наблюдаемая доходность (target) | `R(t,H) = log(S_obs(c, t+H) / S_obs(c, t))` | Один контракт, `t` и `t+H` — торговые сессии по биржевому календарю (ADR-06) |
| Скрытая доходность | `R*(t,H)` | `log(S*(c,t+H) / S_obs(c,t))` |
| Правдоподобие | — | B0/B1: эмпирическое по `R`; B2+: по `R*` с цензурированием |
| Scoring | — | **Всегда по `R`** (наблюдаемый settlement), для всех моделей одинаково |

### 2. Target

`R(t,H) = log(S_obs(c,t+H) / S_obs(c,t))`, `H ∈ {5, 21}` торговых сессий.

- Обе цены — settlement одного и того же контракта; сессия определяется
  торговой датой биржи (включая вечернюю часть предыдущего календарного дня).
- Если контракт не имеет settlement в `t+H` в пределах окна пригодности
  (ADR-06), метка не создаётся; ролла нет.
- `S_obs ≤ 0` или отсутствует → метка не создаётся, факт регистрируется
  в data-quality отчёте. Логарифм константой не «чинится».
- В обучение допускаются только метки, у которых сессия `t+H` и
  публикация её settlement не позже training cutoff (ADR-05).

### 3. Лимитные дни — данные (с фазы 0)

С фазы 0 для каждой пары (контракт, сессия) хранятся:
- применимый дневной лимит (значение, единицы, источник правила, дата вступления);
- расширен ли лимит в этот день по правилу биржи;
- флаг `limit_state ∈ {none, up, down, unknown}` для settlement: `up`,
  если `S_obs(τ) − S_obs(τ−1)` равно применимому лимиту вверх **точно**
  (с точностью до шага цены), и аналогично вниз;
- применимость лимита к сессии (для спот-месяца лимиты могут не применяться
  в период поставки — подлежит проверке по правилам CME для каждой эпохи).

Историческая шкала лимитов (фиксированные значения в ранние годы,
переменные, пересматриваемые периодически, в поздние — **подлежит
проверке по первоисточнику CME/CBOT**) должна быть получена из
документов биржи с датами вступления. **Угадывание лимитного дня по
величине доходности без документированной шкалы запрещено.** Если шкалу
восстановить нельзя — `limit_state = unknown`, и это блокер данных для
соответствующего периода (раскрывается в dataset manifest).

### 4. B0 и B1 (фаза 1)

B0/B1 моделируют непосредственно наблюдаемую величину `R`, которая
по построению включает эффект лимита (settlement — то, что реально
опубликовано). Поэтому использование `R` на лимитных днях в
эмпирических распределениях B0/B1 — это модель наблюдаемого target,
а не трактовка скрытой величины как неограниченной. Дополнительно:

- доля training- и OOS-меток с `limit_state ∈ {up, down}` в конечной
  точке `t+H` раскрывается по культурам и годам;
- чувствительность: B0/B1 с исключением меток, у которых конечная точка
  лимитная, **из обучения** (scoring — по-прежнему на полном наборе).

Вопрос аудитору: признаётся ли это соответствующим §2.5 для фазы 1.

### 5. B2+ (фаза 2) — цензурированное правдоподобие

Согласование противоречия §3/§9: **флаги — с фазы 0, цензурированное
правдоподобие — в B2 (фаза 2)**, как в §9 (более поздний и
операционный раздел); B3 его наследует.

- Метка с `limit_state(t+H) = up`: `R* ≥ R` (правое цензурирование);
  `down`: `R* ≤ R` (левое). Если лимитными были и `t+H`, и промежуточные
  сессии, цензурирование всё равно определяется только конечной точкой:
  внутренние лимитные сессии не делают конечный settlement
  цензурированным, если в `t+H` торговля шла свободно.
- Цензурирование одного дня **не переносится** на горизонт: интервал
  `[R, ∞)` применяется, только если лимитна именно конечная сессия.
- Интервальное цензурирование (если лимит расширялся внутри дня и
  известны обе границы) — поддерживается в likelihood, используется
  только при подтверждённых данных.
- Лимитная начальная точка `t`: `S_obs(t)` — известная reference-цена,
  цензурированием target не является; флаг сохраняется как признак
  качества.

### 6. Scoring B2+ по наблюдаемой величине

Предиктивное распределение наблюдаемого `R` из модели скрытой `R*`:
`R = R*`, если `t+H` не лимитная; иначе `R` = граница лимита. Поскольку
граница зависит от `S_obs(t+H−1)` (неизвестна в `t`), точное
распределение наблюдаемой величины требует модели пути.

Предлагаемое правило: для CRPS используется предиктивное `R*`
(без клиппинга) **с обоснованием** — различие существенно только на
метках с лимитной конечной точкой; их доля измеряется в фазе 0 и
раскрывается. Обязательный срез: метрики на подвыборке без лимитных
конечных точек для всех моделей одновременно (дополнительный, не
основной). Если доля превысит 1% OOS-меток (порог фиксируется здесь,
до данных), правило пересматривается отдельным ADR до OOS фазы 2.

## Последствия

- Фаза 0 обязана собрать шкалу лимитов с датами; без неё лимитная
  разметка `unknown`.
- Сравнения всех моделей идут по одному и тому же наблюдаемому target.
