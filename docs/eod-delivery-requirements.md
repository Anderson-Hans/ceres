# Требование к поставке EOD-цен (предметное, для согласования закупки)

**Версия:** 1.0 · **Дата:** 2026-09-27 · **Статус:** проект требования; закупка не разрешена.
Основание: v0.2 §6.2, §14 п.2–3; рецензия `CERES_PREFLIGHT_REVIEW_v1.0` §8; ADR-02, ADR-06.

Этот документ не является заказом. Покупка и расходы на дополнительные поля
согласуются с владельцем отдельно от разрешения на разработку.

## 1. Инструменты и глубина

| Требование | Значение | Основание |
|---|---|---|
| Контракты | Индивидуальные контракты (не склеенные ряды) CBOT: кукуруза, соя, пшеница SRW Chicago | v0.2 §2.2, §2.5 |
| Контрактные месяцы — обязательно | ZC: декабрь (Z); ZS: ноябрь (X); ZW: июль (N) | v0.2 §2.2 |
| Контрактные месяцы — дополнительно (опция, стоимость раскрыть) | Все листинговые месяцы ZC/ZS/ZW — нужны для индикатора календарного спреда (фаза 3, §8) | ADR-04 п.4 |
| Глубина | Максимум доступного, **не менее 20 лет** | v0.2 §6.2, §14 |
| Разрешение | Только EOD (дневные settlement). Тиковые и внутридневные данные **не закупаются** | v0.2 §6.2, §14 |

## 2. Поля (на контракт × торговую дату)

| Поле | Обязательность | Зачем |
|---|---|---|
| Символ контракта в символогии вендора + маппинг на биржевой код и месяц/год поставки | обязательно | реестр контрактов, отсутствие ролла |
| Торговая дата (trade date биржи) | обязательно | календарь, H в торговых сессиях |
| Settlement price | обязательно | target (ADR-02) |
| Единицы котировки и множитель | обязательно | проверка единиц, отсутствие смешения |
| Volume | обязательно | фильтр ликвидности (ADR-06) |
| Open interest (и дата, к которой он относится) | обязательно | ADR-06; маркеры фазы 3 |
| Признак/дата исправления settlement и исходное значение, если вендор хранит | обязательно запросить; если нет — раскрыть | PIT цен (промпт §4.2) |
| Open/High/Low | опционально | не требуется моделями |
| Метка дня с достигнутым лимитом, действующий лимит, признак расширения | запросить; при отсутствии — источник шкалы лимитов отдельно | ADR-02 |
| Метаданные контракта: first notice day, last trading day, first/last trade date | обязательно (или отдельный документ вендора/биржи) | окно пригодности (ADR-06) |
| Торговый календарь биржи по годам (праздники, ранние/внеплановые закрытия) | обязательно (у вендора или отдельно) | ADR-06 |

## 3. Условия поставки и права

- Формат: CSV/Parquet или API; каждая поставка — с manifest (перечень файлов, число строк,
  контрольные суммы), неизменяемая после поставки; исправления — отдельными поставками.
- Права: использование в исследовательском контуре CERES; **передача аудитору** —
  выяснить заранее. Если запрещена — аудитору предоставляются производные артефакты,
  хэши и процедура воспроизведения в авторизованном окружении (промпт §13).
- Хранение raw вне git (`.gitignore`: `data/raw/`).

## 4. Что раскрыть при коммерческом предложении

Стоимость базовой поставки (п.1 обязательно + п.2 обязательно), стоимость каждого
дополнительного поля/месяца отдельно, фактическая глубина по истёкшим контрактам
каждого месяца, пропуски, наличие истории исправлений, условия передачи аудитору.

## 5. Приёмка поставки (фаза 0)

Проверки: полнота контрактов и дат против торгового календаря; положительность и
единицы цен; отсутствие дублей ключа (контракт, дата); сверка FND/LTD; доля дней с
нулевым объёмом; сверка лимитных дней со шкалой лимитов (где шкала подтверждена).
